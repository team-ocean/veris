# Veris I/O implementation plan

> Superseded output policy (2026-09-15): documentation now lives in `docs/`;
> all driver output is netCDF and command-line parsing uses Click. Histories
> and snapshots always exclude storage halos. Both initial and final
> incomplete averaging windows are discarded. Earlier NPZ/halo/partial-window
> choices below record the original implementation, not the current contract.

> Use superpowers:subagent-driven-development for independent calendar work and
> specialist review; root owns storage, scheduler, integration and pytest scheduling.

**Goal:** Implement the approved calendar-aware h5netcdf input/output subsystem.
**Architecture:** Host-side calendar clock, immutable stream options, sum/count
accumulators and append-only netCDF records, all outside numerical State.
**Tech stack:** Python datetime, NumPy, JAX, h5netcdf, pytest, Sphinx.
**Spec:** docs/superpowers/specs/2026-09-15-io-design.md (approved by user).

## Constraints

Use .venv-latest (existing environment); only one pytest at a time. No snapshots
stored for averaging. No sampling, mutation or files during transformations.
Retain NPZ runner behavior. Full correctness suite precedes any code commit.
