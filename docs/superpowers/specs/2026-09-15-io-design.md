## Architecture

Introduce `veris.io` with calendar arithmetic, h5netcdf storage and a host-side
output manager. Keep clocks, file handles and accumulators outside the array-only
State. Reuse VARIABLES for dimensions and netCDF attributes. Frozen output
configuration and a metadata registry define defaults and documentation.

Each output stream selects variables, a sampling interval and a period:
instantaneous, daily, monthly, annual or a positive fixed timedelta. Multiple
streams can output the same variable with different periods. Each stream is a
netCDF group with its own unlimited time dimension.

Alternatives: kernel-embedded I/O introduces AD side effects; snapshot buffering
grows memory with integration duration. Host scheduling with sums and counts
meets the requested memory and AD requirements directly.

## Calendars and sampling

Gregorian scheduling uses standard-library datetime and timedelta, explicitly
documented and encoded as proleptic Gregorian over datetime's year range.
Model dates are timezone-naive. Fixed calendars use a validated immutable date
type with integer arithmetic: 360_day has twelve 30-day months; noleap always
has 365 days. Support sub-day times and reject invalid dates and intervals.

Drivers provide elapsed model time. Sampling is anchored to the simulation
start, with an optional initial sample. Require integration step boundaries to
reach sampling times exactly; detect missed, duplicate and decreasing sample
times rather than reconstructing unobserved states. Represent time internally
as integer microseconds to prevent cumulative scheduling drift.

Calendar averages align to midnight, month starts or year starts. Fixed periods
align to the simulation start. Windows are half-open [start, end); a sample on
a boundary belongs to the new window. Flush completed windows even when their
boundaries are not sampling times. Skip empty windows. Closing writes a partial
last window by default, with an option to discard it; record partial status,
actual temporal coverage and sample count.

## Accumulation and file contents

Keep one float64 running sum per variable per mean stream and a count; divide
by count when flushing, then reset. No snapshot history. Instantaneous samples
write directly. Transfer arrays to the host only for due samples or explicit
snapshots. Means give every sample equal weight, as requested.

Use h5netcdf for reading and writing. Store time units, calendar, bounds, sample
counts and VARIABLES metadata, including `cell_methods` for point or mean data.
Preserve staggered (x, y) dimension names. Physical output removes halos;
snapshot metadata distinguishes physical arrays from halo-inclusive arrays.
Use context-managed file closure and reject accidental file overwrite.

## Input and final snapshots

Read selected variables from a selected group/record into a named array mapping,
with time metadata. Validate names, dimensions and shapes before updating an
initialized State. Selected-field input is an update, not a complete restart.

Provide final-snapshot writing independent of sampling and averaging buffers.
Support full halo-inclusive State snapshots for lossless round trips, with
Configuration and PhysicalConstants metadata. Also support selected physical
fields. A mean record must not be represented as an instantaneous restart.

## AD and drivers

Explicit disabled/AD mode returns before reading arrays, changing scheduling
state, allocating sums, gathering or opening files. Differentiated integration
does not call the output manager. Guard accidental traced use before any host
effects; tests include grad, JVP, JIT and closed-over constant fields, since
checking a selected array for a tracer alone is insufficient.

After AD, write a concrete final State explicitly outside transformations, for
example using the auxiliary State returned by value_and_grad. Numerical step
functions remain pure.

Add netCDF options and examples to maintained drivers while retaining existing
NPZ behavior. Distributed sampling reuses per-partition halo removal and
collective gathering; all ranks participate and only rank zero writes. No
gathering occurs during AD.
